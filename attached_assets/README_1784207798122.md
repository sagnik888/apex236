# APEX Python Scanner v2.0 — Audited Build

This package is the re-audited Python translation of the uploaded **APEX Hybrid Pro v5.5** Pine Script.

## Files

- `apex_python_scanner.py` — scanner, indicator engine, stateful trade simulator, multi-symbol leaderboard, JSON/CSV utilities and CLI.
- `test_apex_python_scanner.py` — 18 regression and adversarial tests.
- `AUDIT_REPORT.md` — findings, fixes, test coverage and remaining production boundaries.
- `requirements_apex.txt` — runtime dependencies.

## Major corrections in v2.0

1. **Exact Pine/Wilder smoothing** — ATR, RSI, DMI and ADX now use an SMA-seeded RMA instead of pandas' first-value-seeded EWM.
2. **MTF timestamp correction** — open-time and close-time candle feeds are both supported without using future higher-timeframe data.
3. **Daily MTF correction** — previous-day regime data now maps from the immediately preceding trading session rather than lagging by two sessions.
4. **Instrument aliases** — common symbols such as `NIFTYBANK`, `NIFTY FIN SERVICE` and Midcap aliases are detected correctly.
5. **Strike rounding** — ATM selection uses half-up rounding; Python bankers rounding is no longer used.
6. **Gap-safe stop geometry** — SL1 and SL2 are forced onto the protective side of the actual next-bar entry after gaps.
7. **Session scope correction** — NSE/BSE cash-session filtering is not incorrectly forced onto commodity, forex or crypto instruments.
8. **Pending-order correction** — last-bar entry control works, pending intents remain available to the OMS, and stale entries can be cancelled outside the valid session.
9. **Options order-side safety** — a bearish options signal is represented as **BUY PE**, not SELL PE. Underlying direction remains `SHORT`.
10. **Dynamic-score deadlock fix** — the loss-adjusted minimum score cannot exceed the 0–100 score scale.
11. **Input validation** — infinite, zero or negative OHLC prices are rejected; configuration validation is stricter.
12. **Live rolling window** — `max_input_bars` can cap recomputation for faster repeated scans.

## Timestamp configuration

TradingView and most broker candle APIs label a bar by its **open time**, which is the default:

```python
config = ApexConfig(timestamps_are_bar_close=False)
```

Use this only when the input timestamp identifies the completed candle's close:

```python
config = ApexConfig(timestamps_are_bar_close=True)
```

The scanner records both `bar_open_time` and `bar_close_time` in its output.

## Basic usage

```python
import pandas as pd
from apex_python_scanner import ApexConfig, ApexScanner

nifty = pd.read_csv("NIFTY50_1m.csv")
banknifty = pd.read_csv("BANKNIFTY_1m.csv")

config = ApexConfig(
    min_score=70,
    conflict_margin=20,
    use_htf=True,
    entry_delay_bars=1,
    realistic_fills=True,
    timestamps_are_bar_close=False,
    allow_entry_on_last_bar=True,
)

scanner = ApexScanner(config)
leaderboard, results, errors = scanner.scan_many({
    "NIFTY50": nifty,
    "NIFTYBANK": banknifty,
})

print(leaderboard)

result = results["NIFTY50"]
intent = result.order_intent()
if intent is not None:
    print(intent)
```

## Live scanner mode

For repeated scans, use a rolling history window large enough for EMA200 and 15-minute features:

```python
config = ApexConfig(
    max_input_bars=800,
    keep_full_history=False,
    allow_entry_on_last_bar=False,
)
```

With `allow_entry_on_last_bar=False`, an entry due on the final row remains a pending `OrderIntent` for the external OMS instead of being backfilled historically.

## CLI

```bash
python apex_python_scanner.py NIFTY50_1m.csv BANKNIFTY_1m.csv \
  --output scanner_output.csv \
  --details-dir apex_results
```

For close-time-stamped candles:

```bash
python apex_python_scanner.py NIFTY50_1m.csv --timestamps-are-close
```

Validation:

```bash
python apex_python_scanner.py --self-test
python -m unittest -v test_apex_python_scanner.py
```

## Important boundaries

- The scanner emits underlying-price signals and order guidance. It does not authenticate with a broker or place orders.
- Options output is strike and CE/PE guidance only. It does not model option premium, expiry, IV, Greeks, spread or contract liquidity.
- T1/T2/T3 are tracked as price milestones; the translated source does not execute partial target exits or automatically close at T3.
- Backtest P&L does not include brokerage, taxes, exchange fees, spread or latency.
- The scanner recomputes the selected history window. A large 100–200 symbol one-minute deployment should add persistent per-symbol state, websocket candle aggregation and OMS idempotency.
